Automating twice-weekly engineering releases, PR cherry-picking, and feature-flag-safe docs from Slack

Case study · Engineering & Release Ops

Agents GTM

Turning a manual, multi-step release coordination chore into an end-to-end Slack workflow that cherry-picks tagged PRs, deploys with one click, and updates docs without leaking feature-flagged code.

1. The Challenge

Shipping twice a week meant our engineering and GTM teams were constantly coordinating release branches, cherry-picking last-minute fixes, verifying staging builds, and writing release notes and documentation updates under tight deadlines.

Three friction points slowed down every cycle:

  1. Rebuilding vs. Cherry-Picking: When a bug fix needed to land in an active release candidate, manually cherry-picking commits or rebuilding the release branch from scratch ate up engineering time.
  2. Scattered Release Coordination: Status checks, QA sign-offs, and deploy triggers happened across multiple tools and threads.
  3. Feature-Flag Leaks in Docs & Release Notes: Merged PRs often contained code tucked behind feature flags that wasn't ready for customers yet. Summarizing all merged PRs blindly risked announcing unreleased features in public docs and changelogs.

2. The End-to-End Automated Release Flow

I automated the entire release lifecycle so the whole workflow runs through our #release channel in Slack:

  1. Scheduled Twice-Weekly Release Kickoff: Releases start automatically twice a week, cutting the release candidate and opening the coordination thread in our Slack release channel.
  2. Tag-Driven PR Cherry-Picking: When engineers need to push a fix into an existing release candidate, they simply tag the PR. The automation cherry-picks the tagged PR and merges it cleanly into the release branch so we never have to rebuild everything from scratch.
  3. One-Click Go-Live in Slack: Once QA testing is complete, all bugs are cleared, and the version is marked stable, shipping to production is a single button click directly inside Slack.
  4. Feature-Flag-Aware Docs & Release Notes: As soon as the release goes live, the pipeline inspects the merged changes alongside our feature flag configurations in code. Anything gated behind an inactive feature flag is automatically filtered out, while publicly live features and fixes are synthesized into updated documentation and release notes.

3. Results & Impact

  • ~2 hours saved on every release (~4 hours/week): Eliminated manual branch wrangling, cherry-pick coordination, and changelog drafting across our twice-weekly release cadence.
  • Zero accidental leaks of unreleased features: By verifying feature flag configs directly in code before generating docs and release notes, our public documentation stays immediately up to date after every deploy without ever exposing dark-launched work.
